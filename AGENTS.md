## Tech Stack

- Python 3.13, venv at `./venv/`
- Milvus Standalone at `192.168.1.83:19530` via `SESSIONFLOW_MILVUS_URI` (fallback: Milvus Lite at `~/.sessionflow/milvus.db`)
- HNSW index (COSINE, M=16, efConstruction=256) on Standalone
- mlx-embeddings with EmbeddingGemma-300M (Apple Silicon Metal)
- HTTP MCP server on port 7102 (Starlette + Uvicorn)
- SQLite FTS5 sidecar for hybrid vector + keyword search
- Reciprocal Rank Fusion (RRF) merge

## Operational Gotchas

- **MLX Metal SIGSEGV under sustained load** — EmbeddingGemma crashes GPU driver after ~50min continuous compute. Backfill throttle is 200ms between inserts. Do not reduce below 100ms.
- **One MLX thread (SESF-72)** — MLX's Metal command encoder is not thread-safe, and two threads evaluating at once SIGSEGV the server. In server mode `rag_engine.embed_texts` routes every caller to the `mlx-embed` executor, and `_mlx_eval_lock` covers inline callers. Async code must use `search_async` / `add_turns_async`, never the blocking `search()` / `add_turns()`, on the event loop.
- **Milvus Lite gRPC keepalive** — only applies when `SESSIONFLOW_MILVUS_URI` is unset (Lite fallback). Standalone doesn't need the workaround.
- **Backfill checkpoints every 100 files** — `index_state.json` saves progress. Restart picks up from last checkpoint.
- **The last turn stays open (SESF-74)** — the watcher and the provider backfill parse transcripts mid-turn. `transcript_parser.parse_transcript_incremental` emits the open last turn and returns `resume_offset` at its user line, so the next parse rebuilds it with its reply. State keeps `last_byte_offset` (resume) and `consumed_offset` (bytes read); backfill and the Claude provider compare file size with `consumed_offset`. Parser turns carry `REPLACE_SAME_TURN`, and `rag_engine._replace_stale_turns` deletes other `chunk_type == "turn"` rows of the same session and `turn_index` after each `add_turns`, also when the new `doc_id` was already indexed. The open turn re-embeds each time its text changes. `cleanup.py dedupe-turns` repairs rows indexed before this: it re-parses affected sessions on disk and keeps the longest row where the transcript is gone. It is a dry run by default, and `--apply` refuses without `--yes`.
- **`project_root` for `-/` transcripts** — generic bucket sessions have `cwd="/"`. No project tagging possible.
- **Never create GitHub issues** — all issues go to Plane via `/issue` (which reads the `plane` block in `.claude/project.json`).
- **Port binds before startup finishes (SESF-70)** — `lifespan` yields at once. `_background_startup` then loads the model and Milvus on its own executor and starts the workers and watcher. `/health` returns 503 `status: "starting"` until it is done, so `curl -sf` health checks wait for full readiness. Don't move slow work back in front of the `yield`, or MCP clients that connect at login get ECONNREFUSED. Claude Desktop launches `mcp-remote-wait.sh`, which waits for the port, instead of calling `npx mcp-remote` directly.
- **Desktop MCP bridge lives on the internal disk (SESF-71)** — Desktop's MCP child is its own TCC-responsible process and cannot read `/Volumes/DATA`, so pointing the config at the repo copy fails with `Operation not permitted`. Run `./sessionflow-server.sh install-mcp-bridge` to copy `mcp-remote-wait.sh` to `~/.local/bin/sessionflow-mcp-remote`, and point the Desktop `sessionflow.command` there. Re-run it after every change to the script; `mcp-bridge-status` reports drift. The bridge waits with no cap and nudges the LaunchAgent with `launchctl kickstart` while the port is refused. Keep it free of repo paths at runtime.
- **Claude Code headers helper (SESF-83, SESF-84)** — Claude Code runs `headersHelper` with its working directory set to `~/.claude`, not the project, and does not set `CLAUDE_PROJECT_DIR`. `mcp-headers-helper.sh` takes the project from `CLAUDE_PROJECT_DIR`, else the parent `claude` process's working directory (`lsof`, or `/proc` on Linux), then its git root. It prints `{}` for `/`, the config folder or `~/.claude/spares/`, so the server sees no current project instead of a wrong one. Claude Desktop starts each Code-tab session in a `spares/` folder and enters the project only after MCP servers connect, and the header is fixed for the connection. Desktop and Codex sessions therefore send no header; Claude Code clients are scoped by their MCP roots instead (see MCP roots). Run `./sessionflow-server.sh install-headers-helper` after every change to the script; `headers-helper-status` reports drift.
- **Provider backfill controls (SESF-6)** — multi-harness ingestion (`codex`, `opencode`, `antigravity_cli`, `antigravity_desktop`) shares one embedding budget. Tune via `SESSIONFLOW_EMBED_BATCH_SIZE`, `SESSIONFLOW_EMBED_COOLDOWN_MS` (floor 200ms — MLX Metal SIGSEGVs lower), `SESSIONFLOW_BACKFILL_MODE` (`recent`|`incremental`|`full`), `SESSIONFLOW_BACKFILL_MAX_TURNS_PER_RUN`, `SESSIONFLOW_BACKFILL_MAX_FILES_PER_RUN`, `SESSIONFLOW_BACKFILL_RECENT_DAYS`, `SESSIONFLOW_BACKFILL_PAUSED`. Pause/resume + per-provider control via `python cleanup.py backfill {status|pause|resume|enqueue} [--provider <name>]`. Queue state is durable across restarts.
- **Claude Desktop is `claude_code_cli` (SESF-59)** — Desktop Code-tab sessions, former CoWork projects included, write normal transcripts to `~/.claude/projects/` and are indexed as `claude_code_cli`. The `claude-code-sessions/**/local_*.json` files are only metadata pointing at those transcripts (`cliSessionId`), so the old `claude_desktop_cowork` probe was retired. Legacy Cowork agent-mode transcripts under `local-agent-mode-sessions/` are a separate provider, `claude_cowork_legacy` (SESF-60).
- **Codex external imports are skipped (SESF-66)** — Codex Desktop can import Claude Code sessions into a rollout. Their turns start with a `task_started` event whose `turn_id` begins with `external-import-`. `provider_codex.CodexAdapter.parse_source` skips them, because the original transcript is indexed as `claude_code_cli`. Native turns after an import in the same rollout are kept. `cleanup.py prune-codex` deletes indexed import turns whose rollout is still on disk. Import turns of a deleted rollout stay, because their original may no longer be indexed.
- **Legacy Cowork agent mode (SESF-60)** — `claude_cowork_legacy` ingests `local-agent-mode-sessions/*/*/local_*/.claude/projects/**/*.jsonl` with the inherited CLI parser. Subagent transcripts are included; `audit.jsonl` is skipped. The transcript `cwd` is a VM path (`/sessions/<name>`), so `project_root` comes from the sibling `local_<id>.json`. It uses `userSelectedFolders[0]`, else a non-sandbox `cwd`, else `unknown`. No other metadata key is read. This is a one-time source and is not in the startup backfill list. Enqueue it with `cleanup.py backfill enqueue --provider claude_cowork_legacy --mode full`. Desktop may prune or move the folder (Unified Claude, 2026-11-10). To re-ingest from a backup, set `SESSIONFLOW_COWORK_LEGACY_ROOT` to the copy.
- **Project scope (SESF-64)** — `project_scope.resolve_project_scope` turns the `project_root` argument (else the client's MCP roots, else the `X-Project-Root` header) into a list of indexed roots. A path covers its subfolders, and a path inside `.worktrees/` or `.claude/worktrees/` resolves to its repository. An unindexed path falls back to its nearest indexed parent, and a bare name matches root basenames case-insensitively. A miss searches every project. With none of these, the scope is unnamed, and `search_all_sessions`, `search_session` (without a `session_id`) and `get_session_stats` refuse the call (`tools.UNNAMED_SCOPE_ERROR`); their descriptions (`tools.SCOPE_INSTRUCTION`) ask the model to pass its working directory or `'*'`. Search and stats output opens with a `Scope:` line that names the roots and the reason. Known roots come from `rag_engine.known_project_roots` (FTS `DISTINCT`, cached `KNOWN_ROOTS_TTL_S`). Codex worktrees under `~/.codex/worktrees/` sit outside the repo path, so only a name lookup reaches them.
- **MCP roots and stateful sessions (SESF-86)** — `http_server.session_manager` runs stateful, streamed sessions (`stateless=False`, `json_response=False`) so a tool call can send `roots/list` to the client. `client_roots.project_root` asks once per MCP session on the tool call's own stream, waits at most `ROOTS_TIMEOUT_S`, and keeps the first `file://` root; `notifications/roots/list_changed` clears every cached answer. Claude Code (CLI and Desktop Code tab) answers with its working directory; Codex declares no roots and still relies on `project_root`. Every `/mcp/` caller must initialize, send `Mcp-Session-Id` on later requests, accept `text/event-stream` and read the SSE `data:` line. `hooks/memory-session-start.py` does this and deletes its session. After changing the hook, copy it to `~/.claude/hooks/` and `~/.codex/hooks/` (`setup.sh` does this) before restarting the server. Idle sessions expire after 30 minutes and a restart drops them all; clients get 404 and re-initialize.
- **Moved project folders (SESF-73)** — project filters cover a root and its subfolders, but turns tagged with a folder's old path are missed. `SESSIONFLOW_PROJECT_PATH_MAP` rewrites the root at ingest. Its format is `old=>new` pairs separated by `;`. Both sides are absolute paths. The longest prefix wins, and a prefix only matches whole path components. Only `claude_cowork_legacy` reads it so far. launchd does not pass shell env, so set it in the LaunchAgent plist (or `launchctl setenv`) before a re-ingest. To fix rows already indexed, run `cleanup.py retag-project --from <old> --to <new> [--provider P]`. It is a dry run by default, and `--apply` refuses without `--yes`. It calls `rag_engine.update_row_metadata`, which rewrites Milvus and FTS but keeps the stored vector. It also reads FTS, so a re-run picks up any turn whose FTS rewrite failed.
- **Hosted embeddings deferred** — SESF-6 keeps embedding fully local (MLX). No hosted/OpenAI setup steps, credentials, or collections exist. Future hosted path would require a separate identity/collection to avoid vector mixing.
- **Optional LaunchAgent for multi-harness startup** — `./sessionflow-server.sh install-agent` writes `~/Library/LaunchAgents/cc.lbruton.sessionflow.plist` so the server starts at login before any harness hook races. OPTIONAL — `start/stop/status/restart` behavior is unchanged when not installed. `agent-status` / `uninstall-agent` manage it. `setup.sh` honors `SESSIONFLOW_INSTALL_AGENT=1` for non-interactive installs.
- **Optional hourly backfill LaunchAgent (SESF-7)** — `./sessionflow-server.sh install-backfill-agent` writes `cc.lbruton.sessionflow-backfill.plist` with a `StartInterval` (defaults to 3600s; override via `SESSIONFLOW_BACKFILL_INTERVAL_SECONDS`). It runs `python cleanup.py backfill enqueue --provider claude_code_cli --mode incremental`, decoupling catch-up indexing from MCP session activity. MCP-client SessionStart hooks should connect to the already-running server rather than racing to start it.
- **Schema drift (SESF-11)** — `_ensure_collection` refuses to start when the live Milvus schema differs from `_expected_schema_fields()`. Drop+recreate is opt-in via `SESSIONFLOW_AUTO_MIGRATE_SCHEMA=1`, or run `python cleanup.py migrate-schema` explicitly (destructive).
- **`SESSIONFLOW_BACKFILL_MAX_TURNS_PER_RUN` (SESF-12)** — default raised from 200 to 100,000 so a long-running server isn't silently capped after a few minutes. The budget logs a single WARN the first time the cap is hit so operators don't have to grep for "0 turns" lines.
- **FTS5 thread affinity (SESF-13)** — `FTSIndex` keeps per-thread persistent connections (`threading.local`). Server-mode connections opened on the embed executor and request threads are isolated, and cross-thread `close_all()` is a no-op rather than a noisy WARN.
- **OpenCode timestamps (SESF-14)** — `provider_adapters.normalize_timestamp()` coerces int-ms epochs (and any other numeric/datetime input) to ISO-8601 strings before they hit Milvus's `VARCHAR(64)` timestamp field. All four provider adapters route timestamps through it.
- **Harness boilerplate is stripped at ingest (SESF-66)** — `rag_engine._apply_boilerplate` runs `boilerplate.strip` once in `add_turns`, after the doc_id dedup and before redaction and issue-ID extraction, so every provider is covered. It removes task notifications, side-session events, CI-monitor events, system reminders, compaction summaries, local-command output and `!` shell output. Slash-command echoes become `[/name args]` and shell input becomes `[! command]`. A block counts only when its tag opens a line, so a tag quoted in a sentence stays. A turn that stripping leaves under `MIN_TURN_CHARS` is dropped. `SESSIONFLOW_STRIP_BOILERPLATE=off` disables it; counts surface in `get_stats` under `boilerplate`. `cleanup.py reembed` re-embeds the stored `document` as it is and never calls `boilerplate.strip`; rows indexed before stripping are fixed by `cleanup.py rewrite`.
- **In-place rewrite of stale rows (SESF-62, SESF-66)** — `rewrite.py` (`cleanup.py rewrite {plan|run|drive|status|verify}`) selects rows whose `document` `boilerplate.strip` would change, plus rows longer than `sliding_window` + 1 tokens (counted with the transformers tokenizer from the cached model, which matches the MLX one). Each row is stripped, redacted, re-embedded and upserted by PK with recomputed `issue_ids`, and its FTS row is rewritten; a row left under `MIN_TURN_CHARS` is deleted. It reuses `reembed`'s worklist snapshot, chunked `drive`, checkpoint (`~/.sessionflow/rewrite_state.json`) and memory-generation bump. Old documents go to `~/.sessionflow/audit/rewrite-<run>.jsonl` and old vectors to `.f16`; stripped text cannot be rebuilt when the transcript is gone. A failed FTS write stays in `fts_retry` and is retried first by the next run, and the run is `done` only when none is pending. `plan` scans Milvus and writes nothing; `run`/`drive` refuse without `--yes`.
- **Secret redaction guard (SESF-41)** — ingestion-time redaction hooked once in `add_turns` (covers the embedding, Milvus `document`, and FTS `content` sinks plus `add_turns_async`, and runs before `_extract_issue_ids`). Pure engine in `secret_redaction.py`: `redact(text, *, mode, allowlist) -> (redacted_text, hits)`. Config: `SESSIONFLOW_REDACT` (on/off, default **on**); `SESSIONFLOW_REDACT_MODE` (`enforce`|`report`, default **report** when unset — detect + count, store raw so operators can size the false-positive rate before enforcing); `SESSIONFLOW_REDACT_ALLOWLIST` (path to an operator regex allowlist, one pattern per line). Per-rule detection counts surface via `get_stats` under the `redaction` key. Tier-3 entropy is a length-gated Shannon scanner (detect-secrets' entropy plugins are unused — `scan_line` ignores their limit); GitHub/GitLab use custom regexes (detect-secrets reports a truncated prefix).
- **EmbeddingGemma padding mask (SESF-57)** — mlx-embeddings 0.0.5 hands the 0/1 tokenizer mask to SDPA as an *additive* float mask, so padding leaked into shorter docs in a batch. `rag_engine._embed_gemma` runs the gemma forward itself with a boolean key-padding mask (`_key_padding_mask`). Batched now matches single to cos ≥ 0.99999, and a batch of one (every query) is unchanged. `tests/test_embed_padding.py` pins this, so don't revert to calling `model(input_ids, attention_mask=...)`. Sliding layers keep only keys within `sliding_window` (512) of each query, the inclusive bidirectional radius Hugging Face uses, and global layers (every `sliding_window_pattern`-th) see every real key; `tests/test_sliding_window.py` pins this (SESF-62). Texts of 513 tokens or fewer embed exactly as before. Rows over that length stored before the fix keep their old vectors until `cleanup.py rewrite` re-embeds them. Stored vectors were rewritten in place by `reembed.py` (`cleanup.py reembed {plan|run|drive|status|verify}`; chunked under the MLX crash limit; old vectors backed up to `~/.sessionflow/audit/reembed-<run>.f16`).
- **Memory store is Postgres (DEVS-145)** — memories commit to Postgres first; the Milvus `memories` collection and `~/.sessionflow/memories_fts.db` are derived indexes. The DSN comes from `SESSIONFLOW_MEMORY_DSN` only: SessionFlow calls no secrets tool and reads no DSN file, so a launchd install sets it in the LaunchAgent environment. Memory starts after transcript startup on its own thread; a missing DSN or a down database leaves `/health` `memory.ready` false with the reason and transcript search untouched. Blocking store calls go through `memory_store.run_db` (the `memory-db` executor), never the event loop or `mlx-embed`.
- **Never write a memory index directly (DEVS-145)** — every write goes through `MemoryService` to Postgres, which resets that memory's rows in `memory_index_acks` in the same transaction. The sync loop (`SESSIONFLOW_MEMORY_SYNC_INTERVAL`, plus a full reconcile at start and every 6 hours) applies what each consumer (`milvus`, `fts:<host>`) lacks, this host's FTS first, and skips a Milvus record another server already acknowledged. Each tick and reconcile is bounded by `SESSIONFLOW_MEMORY_TICK_TIMEOUT` (600 s): a timeout logs every asyncio task's await chain, cancels the work and lands in `/health` `memory.sync_error`, and `memory.index.stale` turns true when `last_tick` falls behind. A failed reconcile retries after 300 s, and a pass is skipped while three of the four memory-db workers are busy (`memory_store.db_calls_in_flight`), because a cancelled `run_db` await leaves its thread running. `kill -USR1 <pid>` logs the same task dump on demand; thread profilers such as py-spy cannot see suspended coroutines. A Milvus write re-reads the row under `pg_advisory_xact_lock` and upserts only if the embedded hash still matches; the FTS file keeps a per-record watermark so an older write cannot revive a deleted record. `change_seq` orders work but does not follow commit order, so pending work is decided by acknowledgements, not by a cursor.
- **Memory embeds share the MLX thread (DEVS-145)** — `memory_index.embed_for_index` waits on `embedding_control.EmbedThrottle` (200 ms floor) and runs on `mlx-embed`, where it waits again and stamps the throttle; it never uses the transcript budget, which drops batches. `EmbeddingBudget.before_batch` honors the same throttle, so neither consumer starts inside the other's cooldown. `memory_cli` never embeds: `rebuild` and `reindex` only reset acknowledgements, and `restore-check` asks the running server's loopback `/memory/restore-check` route to index into a temporary `memories_restore` collection.
- **Memory embedding generation (DEVS-145)** — `memory_index_meta` names the memory model and generation. `cleanup.py reembed` starts a new generation on a fresh run and resets the Milvus acknowledgements; the server re-embeds from Postgres text. A server whose local model differs refuses memory vector writes and vector searches (`MemoryModelMismatch`; search answers from FTS) and reports it in `/health` (`memory.index.milvus_blocked`).
- **Memory secret check (DEVS-145)** — `add_memory` rejects text with any `secret_redaction.scan_spans` hit and names the rule. Paths and code identifiers can trip it; the fix is a narrow pattern in the operator allowlist (`SESSIONFLOW_REDACT_ALLOWLIST`), never a looser rule.
- **Transcript cleanup leaves memory alone (DEVS-145)** — age expiry, `cleanup_sessions`, `sanitize --drop`, `reset` and `migrate-schema` act on `sessions` and `fts.db` only; `reset` and `migrate-schema` say so.
- **Memory tests (DEVS-145)** — Postgres tests need `SESSIONFLOW_TEST_PG_DSN` (one fresh schema per test through the `memory_pg` fixture) and skip with that reason when it is unset; restore-check tests also need `SESSIONFLOW_TEST_PG_RESTORE_DSN` and `pg_dump`/`pg_restore` 17. An autouse fixture clears `SESSIONFLOW_MEMORY_DSN`. `stub_rag_engine` evicts project modules first imported under the stub, so a later test imports them against the real `rag_engine`. pytest prints fixture DSNs in setup errors, so mask `password=` in any shared output.

## Git Rules

- `main` is the default branch
- Branch protections: signed commits + PR required
- Worktree branches for all changes
- **Request a CodeRabbit review on every code PR.** The repo has fewer than 10 stars, so CodeRabbit does not review automatically. Right after opening a PR that touches code (`.py`, shell scripts, tests, or config the server reads), post a PR comment containing only `@coderabbitai review`. Skip it for chore PRs that only change instruction files (`CLAUDE.md`, `AGENTS.md`, `.claude/`, `.agents/`, skills) or docs. Copilot and Codex reviews may run too; request CodeRabbit anyway.

## Versioning

See CLAUDE.md "Versioning". Every `feat` or `fix` PR runs the `release` skill (`.agents/skills/release/SKILL.md`) with `patch`, `minor` or `major` before it is marked ready; the `Version` workflow fails one that does not raise `version.py` and change `CHANGELOG.md`.
